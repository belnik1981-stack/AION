# Инструкции агентам AION

Действуют для всего репозитория. Перед работой прочитайте `docs/PROJECT_STATE.md`,
`docs/CONSTITUTION.md`, актуальные checkpoints и код затронутого пути. История и
тесты имеют приоритет над неподтверждённым описанием.

1. Перед действием проверьте commit, ветку, чистоту дерева, открытые PR и уже
   подтверждённые этапы. Продолжайте с последнего этапа, для которого есть
   проверяемое доказательство. Приёмка использует checkpoint точного commit,
   журнала и состояния данных; повреждённый checkpoint требует нового запуска.
2. Не повторяйте успешно завершённый этап без технической причины. Не называйте
   пробу, mock или сообщение модели реальным испытанием. При нехватке данных
   пишите «не подтверждено», а не PASS.
3. Выполняйте доступные действия самостоятельно в отдельной ветке. Не меняйте
   `master`, не сливайте PR без разрешения владельца, не удаляйте полезную
   историю. Ограничения лицензии и коммерческого использования не меняйте.
4. Используйте только доступные разрешённые инструменты. Живой тест сначала
   проверяет фактический каталог; допускаются только модели с подтверждённой
   нулевой ценой. Секреты не печатайте и не помещайте в Git или отчёты.
5. Проверяйте положительные и отрицательные пути: 401, 429, обрыв, усечение,
   противоречие, ограничение сравнений и целостность исходных данных. Общий
   или неизвестный 429 останавливает запросы. Повторы и исправления ограничены;
   одинаковые неудачные действия не запускайте циклом.
6. Для каждого изменения сохраняйте причину, минимальный diff, результат
   проверки и ограничение в коммите, отчёте или PR. По возможности привлекайте
   отдельного проверяющего. В отчёте различайте реальные вызовы провайдера,
   офлайн тесты с имитацией и внешнюю ошибку.

Актуальные ограничения AION и границы истины определяются `docs/PROJECT_STATE.md`
и `knowledge/truth/`; эти инструкции не расширяют полномочия runtime.
