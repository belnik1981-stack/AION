# ADR-0004: crash-safe JSON-хранилища

Статус: принято и проверено offline
Дата: 2026-10-19

## Контекст

Эпизодическая и долговременная память, `state.json` и
`pipeline_state.json` записывались напрямую. Ошибка чтения любого вида молча
подменялась пустым списком или объектом. При повреждении файла это выглядело как
корректная «пустая память» и следующая запись могла уничтожить доступный контекст.

## Решение

- JSON сначала полностью сериализуется во временный файл в том же каталоге;
- временный файл и каталог синхронизируются, затем применяется `os.replace`;
- перед заменой сохраняется только валидная last-known-good копия `.bak`;
- права новых runtime-файлов ограничиваются режимом `0600`;
- read-modify-write операции памяти защищены process lock и Linux/Termux
  `flock`, поэтому параллельные процессы не затирают обновления друг друга;
- при повреждении основной копии читается валидная резервная копия и выдаётся
  явное предупреждение;
- повреждённая основная копия архивируется перед восстановительной записью;
- если повреждены и primary, и backup, запись блокируется, а оба файла остаются
  неизменными;
- точные дубликаты эпизодического события и long-term lesson повторно не
  добавляются;
- активная эпизодическая память ограничена, а старые события сначала
  fsync-добавляются в проверяемый append-only архив согласно ADR-0013;
- принятый pipeline-ответ не получает общий статус `ok`, если его обязательная
  запись в episodic memory завершилась ошибкой.

`Truth` не использует этот write API и остаётся read-only.

## Проверка

`tests/harness/test_crash_safe_storage.py` выполняет fault injection для:

- валидной записи и backup;
- повреждения primary;
- одновременного повреждения primary и backup;
- отказа финального `os.replace`;
- дедупликации памяти;
- интеграции с engine и server state;
- шести конкурентных процессов;
- безопасного статуса pipeline при ошибке memory persistence;
- архивной ротации, дедупликации всей истории, crash recovery и конкурентных
  записей в отдельном harness ADR-0013.

Тест входит в полный life trial и CI на Python 3.10/3.12.

## Границы решения

- это локальная файловая транзакция, а не распределённая база данных;
- backup хранит только последнюю валидную версию, а Git не используется для
  runtime-данных;
- приватность содержимого памяти и транзакция promotion + audit требуют
  отдельных проверяемых политик.
