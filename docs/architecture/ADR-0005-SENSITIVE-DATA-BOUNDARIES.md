# ADR-0005: границы чувствительных данных

Статус: принято и проверено offline
Дата: 2026-10-19

## Контекст

Пользовательский prompt, модельный ответ и legacy state могли содержать ключи или
токены. Основной pipeline сохранял принятый результат в episodic memory, engine
сохранял single-cycle state, а server сохранял полный pipeline result. Защита
только текста исключения провайдера не закрывала эти каналы.

## Решение

- один детерминированный redaction-модуль используется ingestion, pipeline,
  memory, engine и server;
- распространённые API keys, bearer/JWT, access keys, password assignments и
  PEM private keys заменяются на `[REDACTED_SECRET]`;
- пользовательская задача и подготовленные ответы очищаются до передачи LLM;
- evidence-контекст очищается до включения в prompt;
- весь pipeline result повторно проверяется перед возвратом и записью;
- episodic memory сохраняет только очищенные поля и число замен;
- обнаружение секрета полностью блокирует long-term promotion: частично
  очищенный текст не становится проверенным знанием;
- legacy memory/state очищаются при отображении и перед следующей записью;
- single-cycle engine использует тот же общий runtime-бюджет;
- server не сериализует и не печатает недоверенный текст исключения;
- глубина, число узлов и длина текста ограничены до начала рекурсивной обработки.

## Проверка

`tests/harness/test_sensitive_data_redaction.py` использует только искусственно
собранные во время теста маркеры и доказывает, что они отсутствуют:

- в prompt, переданном fake provider;
- в episodic JSON и выдаче history;
- в engine state;
- в подготовленных multi-model ответах;
- в итоговом pipeline result.

Также проверяются полный запрет long-term promotion и счётчики редактирования.
Тест входит в полный life trial и CI Python 3.10/3.12.

## Границы решения

- pattern redaction не является доказательством обнаружения любого возможного
  секрета; неизвестные форматы требуют добавления отдельного правила;
- пользователь не должен намеренно передавать действующие credentials модели;
- шифрование runtime memory at rest этим ADR не реализуется;
- политика архивирования растущей истории без удаления данных остаётся открытой.
