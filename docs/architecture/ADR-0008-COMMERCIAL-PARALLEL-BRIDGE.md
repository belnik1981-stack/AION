# ADR-0008: параллельная оценка коммерческой зависимости

Статус: принято и проверено offline
Дата: 2026-10-20

## Контекст

В репозитории существовал отдельный расчёт риска коммерческой зависимости, но
он не был связан с многомодельным runtime. Простое подключение такого расчёта к
основному решению создало бы опасную подмену: финансовый или институциональный
интерес сам по себе не доказывает ложность утверждения, а введённые вручную
коэффициенты не являются объективно проверенными фактами.

## Решение

После построения `aion-claim-registry-v1` AION формирует отдельный
`commercial_dependency` view:

- базовый claim registry и итоговый ответ не изменяются;
- показывается сравнение влияния claim с коммерческим слоем и без него;
- коэффициенты принимаются только из ограниченного JSON-файла, заданного через
  `AION_COMMERCIAL_FACTORS_FILE`;
- допускаются только выбранные в текущем запуске модели, не более четырёх;
- значения факторов ограничены диапазоном от `0.0` до `1.0`;
- входные коэффициенты маркируются `user_supplied_unverified`;
- `commercial_causality_verified` всегда остаётся `false`;
- слой не получает полномочий execution, Truth update, auto-learning или
  принятия итогового решения;
- при отсутствии либо отклонении конфигурации основной pipeline продолжает
  работу без коммерческой поправки.

Полные тексты обоснований не возвращаются в runtime result. Сохраняются только
их количество и SHA-256, чтобы уменьшить риск утечки через диагностический
вывод.

Stateful `CommercialDependencyMonitor` применяет тот же отдельный статус и не
получает полномочий основного pipeline:

- каждое изменение выполняется как блокируемый atomic read-modify-write;
- event сначала фиксируется вместе со state в `pending_audit`, затем
  идемпотентно переносится в JSONL по уникальному `event_id`;
- сбой audit append не отменяет уже подтверждённый state, но оставляет явно
  восстанавливаемое pending-состояние;
- два экземпляра monitor, созданные из одного устаревшего снимка, не затирают
  изменения друг друга;
- чувствительные case ids или payload, `NaN`/infinity, неизвестные поля и
  повреждённая структура отклоняются до новой записи;
- число cases, длина истории, pending events и общий размер state ограничены;
  достижение лимита останавливает запись, а не удаляет раннюю историю;
- непосредственно повторённое последнее идентичное событие не создаёт
  дубликат истории или audit.

## Проверка

`tests/harness/test_commercial_parallel_bridge.py` подтверждает, что:

- синтетический профиль высокого риска изолируется только в параллельном view;
- исходный registry остаётся побайтно эквивалентным канонической сериализации;
- Synthesizer и итоговый ответ не получают коммерческий скоринг;
- причинность не объявляется доказанной;
- некорректные и выходящие за диапазон коэффициенты отклоняются fail-closed.

`tests/harness/test_commercial_dependency_layer.py` дополнительно проверяет:

- отсутствие lost update между устаревшими экземплярами monitor;
- восстановление после прерывания между state commit и audit append;
- идемпотентность audit recovery;
- запрет секретов и нефинитных чисел до persistence;
- восстановление валидной резервной копии вместо пустого сброса;
- fail-closed ограничения роста без вытеснения старых событий.

Тест включён в полный offline life trial и обе основные CI-матрицы.

## Границы решения

- оценка показывает последствия заданной гипотезы, а не устанавливает мотив,
  зависимость или недостоверность модели;
- независимая проверка владельцев, финансирования и стимулов этим модулем не
  выполняется;
- отсутствие конфигурации означает `not_configured`, а не отсутствие риска;
- текущая реализация не добавляет поля стимулов в Evidence Objects v2;
- коммерческий слой не может использоваться как автоматическое основание для
  блокировки источника или изменения Truth;
- атомарность state и JSONL реализована восстанавливаемой локальной очередью,
  а не распределённой транзакцией между машинами;
- одинаковое событие после другого промежуточного события считается новым:
  без внешнего observation id monitor не может доказать, что это повтор, а не
  новое наблюдение.
