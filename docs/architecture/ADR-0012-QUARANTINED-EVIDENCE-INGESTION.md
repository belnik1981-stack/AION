# ADR-0012: карантинное преобразование собранных документов

Статус: принято; проверяется offline и в CI
Дата: 2026-10-20

## Контекст

`EvidenceCollector` безопасно получает ограниченный текст публичного документа,
но сам факт сетевой загрузки не доказывает:

- что документ относится к проверяемому утверждению;
- что его автор и происхождение подлинны;
- что несколько доменов являются независимыми источниками;
- что содержание документа истинно или воспроизводимо.

Прямая передача результата collector в runtime создала бы скрытый путь повышения
непроверенного текста до evidence.

## Решение

Добавлен `evidence/candidate_bundle.py`. Он преобразует не более десяти
`EvidenceDocument` в существующий формат Evidence Objects v2, не вводя новый
параллельный контракт.

Каждый автоматически собранный документ получает:

- `RawArtifact` с `privacy_class=private` и
  `access_policy=restricted_analysis`;
- provenance `acquisition_method=api_capture`, но без утверждения времени
  наблюдаемого события;
- `EvidenceObject` с `relation=context`;
- качество `hidden / unavailable / unknown`;
- общий `ClaimObject` типа `assumption`, которому запрещены execution,
  memory promotion, Truth update и network action.

Query и fragment URL не сохраняются в `origin_locator`. Это снижает риск
сохранения tracking-параметров и подписанных URL. Секреты, неограниченные
размеры, неверные типы и более десяти документов блокируют запись.

Пакет сначала создаётся во временном закрытом каталоге, полностью проверяется
валидатором v2 и публикуется без перезаписи существующего пути. Разрешён только
результат со структурным статусом `valid`, но с итоговым токеном `DENIED`, без
qualified support roots и без полномочий исполнения. Запись в `knowledge/truth`,
`memory` и `audit` запрещена.

CLI `tools/prepare_evidence_candidate.py` объединяет bounded collector и этот
writer. Он выводит только безопасную сводку, а не тексты документов и URL.

## Инвариант допуска

```text
network fetch
    -> quarantined RawArtifact
    -> context EvidenceObject
    -> v2 validation = valid / DENIED
    -> runtime bridge rejects
```

Чтобы пакет когда-либо получил `ANALYSIS_ONLY`, отдельный процесс проверки
должен обосновать смысловую связь, качество, свежесть и независимость roots.
Этот ADR такого процесса не имитирует.

## Проверка

`tests/harness/test_evidence_candidate_bundle.py` проверяет:

- детерминированность при перестановке документов;
- удаление query из provenance;
- фиксированные карантинные статусы и качество;
- структурно валидный, но не допускаемый пакет;
- отказ штатного runtime bridge;
- запрет перезаписи и записи в Truth/memory/audit;
- ограниченное потребление iterable;
- блокировку секретов до появления выходного каталога.

Тест входит в `scripts/full_life_test.sh` и CI-матрицы Python 3.10/3.12.

## Границы решения

- `DENIED` — это преднамеренный результат, а не ошибка загрузки.
- URL без query не доказывает владельца, автора или неизменность удалённого
  ресурса.
- Контентный SHA-256 доказывает локальную целостность байтов, но не истинность.
- Автоматическая semantic classification и внешняя authenticity verification
  не реализованы.
- Pattern-based поиск секретов не обнаруживает все возможные виды
  конфиденциальных данных; шифрование at rest остаётся отдельной задачей.
