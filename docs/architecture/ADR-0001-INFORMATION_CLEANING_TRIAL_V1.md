# ADR-0001: изолированный контур испытания очистки информации

Дата: 2026-09-08  
Статус: **ACCEPTED FOR PROTOTYPE TEST ONLY**

## Решение

Первый практический тест EGDE/AION реализуется как отдельный offline-пакет `trials/information_cleaning_v1`. Он не подключается к `core.engine`, provider, памяти или Truth и не получает полномочий на внешние действия.

```text
untrusted fixture
  -> schema validation
  -> normalization + sensitive-data redaction
  -> relevance quarantine
  -> exact-content deduplication
  -> dependency-root collapse
  -> provenance/contradiction policy gate
  -> ANALYSIS_ONLY | DENIED
  -> read-only analytical use
```

## Инварианты

1. Truth не изменяется.
2. Сеть, LLM, API-ключи и Agents SDK не используются.
3. Шум не уничтожается: он переносится в карантин с идентификатором и fingerprint.
4. Противоречащие сведения сохраняются и закрывают допуск при материальном подтверждённом конфликте.
5. Повторения одного dependency root считаются одним корнем, независимо от числа публикаций.
6. `partial` и `unverified` не считаются проверенными корнями.
7. Успешный результат даёт только `ANALYSIS_ONLY`; разрешение на исполнение не выдаётся ни при каких входах v1.
8. Любая ошибка схемы завершает обработку fail-closed.
9. Совпадающий текст с противоречащими метаданными не скрывается дедупликацией: такой набор получает `DENIED`.
10. Downstream-функция повторно вычисляет доказательный порог по очищенным evidence records и не доверяет одному входному токену.

## Испытательный доказательный контракт

Это параметры прототипа, а не универсальная формула истины:

| Risk class | Минимум полностью проверенных supporting roots | Поведение при подтверждённом противоречии |
| --- | ---: | --- |
| `low` | 1 | `DENIED` |
| `moderate` | 2 | `DENIED` |
| `high` | 2 | `DENIED` |
| `critical` | 2 | `DENIED` |

Supporting root учитывается, только если его provenance полностью `verified` и существует supporting item с quality не ниже `0.65`. Число `0.65` — параметр проверочного стенда, не «вероятность истины».

## Контрольные сценарии

1. **Negative control из Samsung Notes:** посторонний HTML помещается в карантин; 10 релевантных записей сворачиваются в 2 dependency roots; один root проверен, другой partial; risk=`critical`; результат `DENIED`.
2. **Positive analytical control:** два полностью проверенных независимых root без материального противоречия; результат `ANALYSIS_ONLY`, `execution_authorized=false`.
3. **Contradiction control:** минимальный supporting-порог выполнен, но присутствует проверенное контрдоказательство; результат `DENIED`.

## Рассмотренные альтернативы

- **Сразу подключить `agents-sdk-adapter` к AION:** отклонено до исправления promotion, provenance и learning gates.
- **Очистка посредством LLM:** отклонено для первого теста из-за недетерминированности и зависимости от внешнего provider.
- **Сразу работать с реальными чувствительными данными:** отклонено; сначала требуется безопасный воспроизводимый baseline.
- **Удалять шум без следа:** отклонено; это мешает аудиту и проверке ложных исключений.

## Ожидаемый технический эффект

Появляется минимально проверяемая граница между «материал прочитан» и «материал допущен к аналитическому использованию». Тест способен доказать fail-closed на известном отрицательном сценарии, но не доказывает корректность автоматического определения истины или реальную независимость внешних источников.

Поля `dependency_root`, `root_verification`, `stance`, `relevance` и `quality` в v1 задаются контролируемым fixture. Контур проверяет использование этих полей, но ещё не устанавливает их достоверность по внешнему provenance. Поэтому v1 не является защищённым promotion gate для произвольного ввода.

## Условие следующего этапа

Интеграция с candidate store допустима только после успешного offline-теста, независимого повторения результата и отдельного ADR о формате Evidence Object/Claim Object. Подключение к автономному исполнению требует нового решения и отдельного разрешения пользователя.
