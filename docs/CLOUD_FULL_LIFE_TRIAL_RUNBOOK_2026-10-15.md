# AION — личное испытание на облачном Linux-сервере

Это инструкция для владельца проекта после слияния проверенной версии в `master`. 
Режим по умолчанию — **офлайн**, без внешних моделей, платы за API и необходимости вводить ключ.

## 1. Подготовка Ubuntu/Debian

```bash
sudo apt update
sudo apt install -y git python3 python3-venv
```

## 2. Получить проект

Если проекта ещё нет на сервере:

```bash
git clone --branch master https://github.com/belnik1981-stack/AION.git ~/AION
cd ~/AION
```

Если копия существует, **сначала** посмотрите `git status --short` и сохраните свои изменения при их наличии; затем:

```bash
cd ~/AION
git fetch origin master
git switch master
git pull --ff-only origin master
```

## 3. Одна команда личной офлайн-приёмки

```bash
cd ~/AION && bash scripts/owner_acceptance_test.sh
```

Launcher сначала требует чистый актуальный `origin/master`, затем создаёт
изолированную локальную копию точного commit. В ней он создаёт отдельную
Python-среду, проверяет сценарии очистки, доказательства, границы автономности,
мультимодельный режим на имитациях ответов, зацикливание, безопасность
веб-сервера и неизменность Truth. Основная runtime-память checkout до и после
сравнивается и не используется тестовой копией.

При успехе: `[ACCEPTANCE PASS]`. При ошибке выполнение останавливается
с ненулевым кодом и конкретным последним шагом. Отчёты:
`~/AION/test-reports/owner-acceptance-*.log` и `.json`.
Скрипт не запускает настоящий LLM и не доказывает истинность его ответов.

`bash scripts/cloud_check.sh` сохранён как низкоуровневый запуск полного life
trial текущего checkout; для личной приёмки предпочтителен изолирующий launcher.

## 4. Короткий реальный запрос, до полного испытания (рекомендуется)

Бесплатные модели OpenRouter могут перегружаться (HTTP 429) или тратить токены
ответа на внутренние рассуждения, что приводит к `finish_reason='length'`.
Отличайте эти причины: 429 означает отказ внешнего сервиса; ответ с `length`
намеренно не принимается. Статус `health: ok` проверяет только конфигурацию,
но не подтверждает реальное подключение.

Для **одного** контрольного запроса без автоматических повторов, в Termux или
на облачном сервере (без `sudo` в Termux):

```bash
cd ~/AION
read -r -s -p "OpenRouter API key: " AION_API_KEY; echo
export AION_API_KEY
export AION_MODEL=openrouter/free
bash scripts/live_probe.sh
```

Успех: `[PASS] LIVE SINGLE-REQUEST PROBE: 4`.
`[RATE LIMITED]` означает HTTP 429, и повторять запрос сразу не стоит.
`[TRUNCATED]` означает, что выбранная модель не завершила вывод даже для
контрольного запроса. При перегрузке выбирайте **другую подтверждённую**
бесплатную модель с `:free` или повторите запрос позднее.
Команда не выполняет многоагентный цикл и не подтверждает его пригодность.

## 5. Ограниченный реальный тест двух бесплатных моделей

Запускать только при собственном ключе **OpenRouter** с разрешённым бесплатным
доступом. Команда `read` принимает ключ скрыто, без записи в историю команд:

```bash
cd ~/AION
read -r -s -p "OpenRouter API key: " AION_API_KEY; echo
export AION_API_KEY
bash scripts/owner_acceptance_test.sh --live
unset AION_API_KEY
```

Launcher проверяет текущий каталог и ограниченно ищет два eligible `:free` ID
разных авторов. Это наблюдаемое различие идентификаторов, а не доказательство
независимых обучающих данных. Режим free-only запрещает явно платные модели и
отклоняет ответы с заявленной ненулевой стоимостью, но не гарантирует нулевые
внешние расходы, если провайдер начисляет их до отказа; проверяйте условия и
баланс.

## 6. Явный выбор моделей для live-приёмки (опционально)

При сохранённых переменных окружения предыдущего шага:

```bash
export AION_MODELS='ПЕРВАЯ_МОДЕЛЬ:free,ВТОРАЯ_МОДЕЛЬ:free'
bash scripts/owner_acceptance_test.sh --live
```

Подставьте **две разные доступные модели**. Не используйте `openrouter/free` как
гарантию независимости, поскольку маршрутизатор может выбрать уже указанную модель.
Количество запросов больше, чем в тесте одной модели.

## Безопасность и границы

- Не публикуйте ключ API, журналы с конфиденциальными запросами, порт 8080 без защиты.
- launcher и `cloud_check.sh` не выполняют слияний и не переписывают `master`.
- Наличие `PASS` подтверждает только выполненные тесты, а не абсолютную
  достоверность анализа или независимость провайдеров.
- Для остановки во время исполнения используйте `Ctrl+C`.

## Поведение при ограничениях внешних моделей

- Planner, Analyst, Critic, Verifier и Synthesizer получают независимые бюджеты
  (`AION_PLANNER_TOKENS`, `AION_ANALYST_TOKENS` и др.).
  `AION_MAX_TOKENS` не перекрывает их индивидуальные настройки.
- Дополнительная попытка при обрезанном выводе: **не более одной** на роль;
  увеличение токенов ограничено `AION_ROLE_TOKEN_CEILING` (по умолчанию 4096).
  Отключение: `AION_TRUNCATION_RETRY=0`. Повтор тоже расходует лимит провайдера.
- HTTP 429 не приводит к автоматическим повторным запросам; сообщение очищено
  от сторонних служебных данных. Частые повторные попытки могут усугубить лимит.
- `[PASS] FULL LIFE TRIAL` выдаётся только если многоэтапный ответ имеет
  `status=ok` и непустой итог. Ошибки, отклонённые ответы и остановки по циклу
  нельзя считать успешным полноценным live-тестом.

## HTTP 400 при использовании `openrouter/free`

Маршрутизатор `openrouter/free` может выбрать любую из совместимых
бесплатных моделей. Некоторые модели не поддерживают запрос
`reasoning.effort=none`; они возвращают HTTP 400.
AION теперь **не передаёт** поле `reasoning`, если задано
`AION_REASONING_EFFORT=none` (также при пустом значении), оставляя
решение о внутреннем рассуждении самой модели. Отсутствие параметра **не**
гарантирует отсутствие внутренних токенов рассуждения.

При HTTP 400 AION печатает только известную категорию `error_type`,
если провайдер её предоставил (`unknown` в остальных случаях);
оригинальные сообщения и служебные идентификаторы не печатаются.
Это предотвращает утечки, но не доказывает, что причина именно в reasoning.
Для личного испытания после обновления master:

```bash
cd ~/AION && git pull --ff-only origin master
AION_LIVE_TEST=1 AION_FREE_ONLY=1 AION_MODEL=openrouter/free bash scripts/cloud_check.sh
```

Тесту требуется действительный `AION_API_KEY` в той же сессии Termux.

## Critic: укороченная проверка после ответа `finish_reason=length`

Этап Critic выполняет проверку анализа на существенные противоречия. Для
бесплатных моделей со скрытыми рассуждениями прежних 450 токенов (и
900 при повторе) иногда недостаточно. Теперь по умолчанию Critic запрашивает
1600 токенов, при обрыве делает **не более одного** повтора с 3200 токенами,
если `AION_TRUNCATION_RETRY=1`. Общий потолок запросов ролей по умолчанию
4096 токенов; повышены также бюджеты Verifier и Synthesizer.
Это только верхние лимиты вывода, не гарантии того, что модель их использует
и что выбранный бесплатный провайдер их поддержит.

Локально в Termux, после обновления `master` и задания `AION_API_KEY`:

```bash
cd ~/AION && bash scripts/live_critic_probe.sh
```

При успешном ответе: `[PASS] LIVE CRITIC PROBE: OK`.
Это только проверка отдельной роли на простом контрольном задании,
**не** доказательство исправности всего pipeline или качества независимой
проверки. Если провайдер снова вернул обрыв, не принимать неполный ответ
как успешный. Используйте другой подтверждённый `:free` идентификатор
в `AION_MODEL` или повторите позднее: `openrouter/free` динамически
выбирает доступную бесплатную модель для каждого запроса.


## Проверенная политика выбора бесплатной модели и живое испытание

По официальной документации OpenRouter запрос
`GET /api/v1/models/user` учитывает настройки провайдеров, приватности
и ограничения пользователя. Он предпочтительнее глобального каталога.
Если этот путь возвращает только HTTP 404, допускается чтение публичного
`GET /api/v1/models`; HTTP 401/403/429 **не скрываются** запасным каталогом.

Отбор допускает только `:free` с явными нулевыми ценами prompt/completion,
отсутствием ненулевых дополнительных тарифов, текстовыми входом и выходом,
достаточными бюджетами токенов и неистёкшей датой. Дополнительный endpoint
API никогда не считается достоверной проверкой доступности.

Сценарий `scripts/live_pinned_pipeline_probe.sh` проверяет наличие
реального завершённого ответа, используя **не более двух различных**
допущенных бесплатных моделей на этапе готовности. При HTTP 400, 404,
502/503 либо обрыве вывода первой модели допускается **одна попытка на другой
модели**. При HTTP 429, ошибке доступа, неизвестном отказе запросы
прекращаются немедленно. Если модель указана явно, используется **только она**.
После успешной готовности ID фиксируется на весь многоагентный цикл;
никаких запасных моделей при сбоях уже запущенного цикла.

Для автономной проверки источника моделей добавлен
`OpenRouter public catalog contract` GitHub Actions: тест проверяет
**настоящий публичный** каталог OpenRouter, не использует закрытый ключ
и **не** совершает генеративных запросов. Дополнительно офлайн тестируются
сценарии 400/404/429, обрыва, запрета платной модели и неизменности Truth.

Инструкция запуска обновлённой проверки:

```bash
cd ~/AION && git pull --ff-only origin master && AION_MODEL=openrouter/free bash scripts/live_pinned_pipeline_probe.sh
```

В результате сначала идут `[CATALOG]`, затем `[PREFLIGHT]`.
`[PASS] LIVE PINNED SINGLE-MODEL PIPELINE` и `[PASS] Truth unchanged`
подтверждают только один успешный живой цикл. Необходимо отдельно
проверять реальную достоверность содержания и независимость разных моделей.

Официальный Python SDK OpenRouter изучен как возможная замена
самодельной HTTP-обвязки, но **не внедрён без сравнения поведения**:
автоматические повторы SDK могут противоречить установленной политике
AION при HTTP 429. Из официального API использован пользовательский
каталог; существующие контракты провайдеров и прежние тесты сохранены.


## Реальное испытание двух разных бесплатных моделей

Сценарий использует действующие, ранее проверенные функции отбора
бесплатных моделей и короткого реального тестового запроса. Не запускает
полный `cloud_check.sh`, поэтому не повторяет большие офлайн-журналы.

```bash
cd ~/AION && git pull --ff-only origin master && bash scripts/live_two_model_probe.sh
```

По умолчанию берёт **две разные модели двух разных авторов** из текущего
каталога `/models/user`. Из максимум пяти каталоговых кандидатов
отправляется именно **исходная задача сравнения**, а не посторонний вопрос
`2+2`. Полные ответы двух моделей сохраняются **один раз** и повторно
передаются в цепочку ролей: это позволяет избегать двух дополнительных
запросов и исключает ложное подтверждение только коротким запросом.
При HTTP 429 и ошибках доступа испытание прекращается; при обрезании,
HTTP 400/404/502/503 возможна следующая заранее проверенная бесплатная
модель до достижения максимума. После получения двух завершённых ответов
устанавливается `AION_MODELS` ровно с двумя ID и запускается **один**
ограниченный цикл уже существующих ролей. На этом этапе смена модели
не производится. Ошибки исходных ответов сообщаются отдельной строкой
`[RAW ERROR] <модель> <тип> [HTTP статус]`, без тела ответа поставщика.

Можно вручную закрепить два ID через `AION_MODELS` (разделение запятой).
В этом случае альтернатив не будет. Дубликаты, `openrouter/free` и
два ID одного автора для данного испытания отклоняются до обращения к LLM.

**Признаки проверенного запуска:** `[PASS] TWO DISTINCT MODEL IDS`,
два отдельных `[RAW MODEL]` с краткими фрагментами ответов,
`[PASS] MULTI MODEL PIPELINE`, `[PASS] Truth unchanged`. Формальная
проверка ролями обозначается `verification_scope=llm_review_only` и
`truth_verified=False` даже если обе модели согласны и Verifier ответил
`OK`. Различные ID/авторы не доказывают независимость обучения моделей;
без внешних доказательств нельзя объявлять ответ объективной истиной.

История ошибок (HTTP 400/404/429/502, обрезание токенов, ложный каталог,
переход на один ID) сохранена как регрессионные случаи. Автоматические
проверки использовали реальные данные публичного каталога без генеративных
запросов. Для запуска сравнительного теста с пользовательскими ограничениями
выполняется отдельная команда выше.
